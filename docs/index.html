本地工具 · 使用说明

HTML Fiddle

在本地浏览器里可视化编辑磁盘上的 HTML 文件：双击改文案、面板调样式、 切 Preview 验交互，点 Save 写回源文件。它是从 DSH 插件里把编辑器本体摘出来独立运行的版本， 不需要 DSH、不需要 Node/npm，只要有 Python。

  • 纯 Python 标准库
  • 不需要 Node / npm
  • 首启不联网
  • 127.0.0.1:4318
  • 与 DSH 插件并存

01它是什么

一个"双击就能用"的本地 HTML 可视化编辑器，等于把 DSH 右侧栏里那个编辑器单独拿出来跑。

它做什么

  • 直接在页面上点选元素、改文案
  • 用面板调样式，实时预览
  • 切换 Preview 验证真实交互
  • 点 Save 把改动写回你原来那个文件
  • 文件被别的程序改动时，页面会自动刷新

它不做什么

  • 不做构建、不装依赖、不生成工程
  • 不接管你的文件：写回前有版本校验
  • 只处理 .html（引擎限制）
  • 不对外提供服务：只绑回环地址
  • 不提供单文件 exe（原因见 安全与边界）
一句话理解它：一个纯标准库的本地 HTTP 服务（引擎）＋ 一个 GrapesJS 前端页面（编辑器）。 启动器负责"找 Python → 拉起服务 → 打开浏览器"，仅此而已。

02快速开始

三种启动方式，任选一种。关掉浏览器不会停止后台服务，要停就运行 stop-workbench.bat。

① 双击

双击 start-workbench.bat，它会列出最近编辑过的文件；输入序号即可，或按 n 新建一个。

② 拖拽

把任意 .html 拖到 start-workbench.bat 上直接打开。文件可以在任何目录，不限 pages\。

③ 命令行

习惯敲命令的话，见下方命令行参考。macOS / Linux 用 start-workbench.command。

:: 打开指定文件
start-workbench.bat "D:\work\report.html"

:: 在 pages\ 下新建 landing.html 并打开
start-workbench.bat --new landing

:: 只看最近文件 / 体检服务与离线资源
start-workbench.bat --list
start-workbench.bat --status

:: 停止后台服务
stop-workbench.bat
第一次使用如果只看到 [exit code: 9009]： 这是"Python 没被正确找到"的旧表现，已修复。原因是 Windows 商店的 零字节 App Execution Alias 桩文件（…\AppData\Local\Microsoft\WindowsApps\python.exe） 会被 where python 找到，但它不是真解释器，一执行就返回 9009。 现在入口脚本会逐个真的跑一遍来验证解释器，并按路径直接跳过商店桩文件； 全部失败时会给出明确的安装指引并以退出码 2 结束，而不是把 9009 抛给你。

03运行架构

主链路：双击入口 → 解释器探测 → 启动器 → 本地引擎，再由引擎分出"编辑器界面 / 目标文件 / 离线资源"三条支线。

由 archify 渲染 · 下方为嵌入视图 在新标签页打开可交互版本 ↗
  • frontend（用户界面 / 入口）
  • backend（本地进程）
  • database（本地文件 / 资源）
  • 虚线＝非运行时依赖；绿色加粗＝主链路续接

怎么读这张图

  • 纵向三段是启动链路：start-workbench.bat 先调用 find-python.bat 定下可用解释器，再用它执行 launcher.py。
  • 启动器只做两件事：以后台方式拉起引擎，用 /api/health 探活，然后打开浏览器。
  • 引擎是唯一的中心：它既向浏览器提供编辑器页面（workbench.html + GrapesJS），也接收编辑器发来的保存请求。
  • 写盘由引擎负责：编辑器不直接碰磁盘，保存时带 revision 校验，所以外部改动不会被静默覆盖。
  • 虚线是"离线加载"：GrapesJS 预置在 vendor/，引擎逐字节校验哈希后直接使用，启动不需要联网。

04目录结构

带 ★ 的是本项目新写的部分；其余为上游代码。UPSTREAM.md 记录了完整来源与哈希。

htmlfiddle/
├─ start-workbench.bat      Windows 入口（双击 / 拖拽 / 传参）
├─ stop-workbench.bat       停止后台服务
├─ start-workbench.command  macOS / Linux 入口
├─ scripts/
│  ├─ launcher.py           ★ 启动器：挑文件、拉服务、开浏览器、记最近文件
│  ├─ find-python.bat       ★ 解释器探测：逐个"真的跑一遍"验证，跳过商店桩文件
│  └─ workbench.py          上游引擎本体（MIT，仅一处编码兼容补丁）
├─ assets/
│  └─ workbench.html        上游编辑器前端（GrapesJS，未改动）
├─ vendor/                  GrapesJS 离线资源（哈希与引擎硬编码值一致）
├─ pages/                   新建文件的默认目录（含示例 example.html）
├─ logs/                    运行日志（按端口分文件）
├─ state/                   最近文件记录 / 调用引擎时的中转文件
├─ docs/                    本说明页 + 架构图（可删）
├─ README.md                纯文本版说明
└─ UPSTREAM.md              来源、哈希、补丁 diff、升级步骤

05命令行参考

下面这些参数由 launcher.py 提供，通过入口脚本透传，因此 start-workbench.bat <参数> 直接可用。

参数作用
<文件路径>要编辑的 .html；省略则进入挑选菜单
--new NAME在 pages/ 下新建 NAME.html 并打开
--port N指定本地服务端口（默认 4318，可用环境变量 HWF_PORT 覆盖）
--no-browser不自动打开浏览器，只在终端打印地址
--wait SEC等待服务就绪的秒数（默认 12）
--list列出最近打开的文件后退出
--status体检：服务状态 + 引擎脚本 + 离线资源是否就位
--stop停止指定端口上的后台服务
--version打印版本

不想用启动器也可以直接调引擎（等价用法）：

python scripts\workbench.py open "D:\work\a.html" --vendor-cache vendor --log-dir logs

06故障排查

先跑体检：start-workbench.bat --status。它会把服务、引擎脚本、离线资源三件事一次讲清楚。

现象原因与处理
只看到 [exit code: 9009] 商店的零字节 python.exe 桩文件排在真解释器前面。已修复；若仍出现，说明机器上没有可用的 Python 3.9+。诊断：where python 的第一个结果是否指向 …\WindowsApps\
提示 No usable Python 3.9+ found 确实没装可用的 Python。装 Python 时勾选 "Add python.exe to PATH"，或改装 Miniconda。脚本已跳过商店桩文件并给出这条指引
提示端口被占用 换端口：start-workbench.bat --port 4399 "D:\x\a.html"
浏览器打开是空白 / 报错 看 logs\workbench-<端口>.log；确认 --status 里引擎脚本与前端页面都"存在"
报 VENDOR_DOWNLOAD_FAILED vendor/ 被删或哈希不符（引擎逐字节校验）。放回那两个文件即可，或允许它联网重下
保存被拒绝（提示冲突） 这是保护机制：文件在你编辑期间被别的程序改过。刷新页面拿到最新版本再改
服务停不掉 先 stop-workbench.bat；若端口被别的程序占用，用 --port 换端口，或手动结束该进程

杀毒软件 / 防火墙可能对"启动本地服务并打开浏览器"告警，选择允许即可（仅回环地址，不对外）。

07与上游 DSH 插件的关系

两者完全独立、可以并存。端口刻意错开，所以停止本项目不会误杀 DSH 拉起的服务。

DSH 插件HTML Fiddle
默认端口43174318（可用 --port 改）
界面位置DSH 右侧栏面板你自己的浏览器标签页
启动方式DSH 载入插件时自动双击 start-workbench.bat
文件来源自动跟踪 agent 刚写出的 html你挑的 / 拖拽的文件
选中文案喂给 AI生成 chip 塞进聊天输入框生成选区 Markdown 并复制到剪贴板

代码从哪里来

  • 引擎 scripts/workbench.py 与前端 assets/workbench.html 取自 @vibe-x/dsh-html-workbench（MIT）。
  • 前端未改动；引擎只有一处兼容补丁：把三处 subprocess 调用的输出解码加上 errors="replace"， 修掉简体中文 Windows 上 stop 会抛 UnicodeDecodeError 的上游问题（详见 UPSTREAM.md）。
  • vendor/ 里两个文件的哈希就是引擎中硬编码的期望值，逐字节一致，所以启动时校验通过、直接本地加载。

脱离 DSH 后唯一失去的能力是"选中文案直接变成聊天框里的 chip"：上游前端本来就内建了 "不在 iframe 里就退回剪贴板"的降级逻辑，所以替代方案就是剪贴板。 其余功能（编辑、保存、预览、样式面板、外部改动自动刷新）都来自引擎，独立运行时一模一样。

08安全与边界

服务没有任何鉴权。它只监听 127.0.0.1，不对局域网暴露， 但本机上任何程序都能通过 http://127.0.0.1:4318 读写你正在编辑的那个 html 文件。 所以：不要把端口转发出去，也不要在不可信的多用户机器上长期挂着。
  • 引擎可以打开任意路径的 .html，不限于 pages/。
  • 保存带 revision 校验：文件被外部改过时保存会被拒绝（409 REVISION_CONFLICT），而不是覆盖。
  • 保存时引擎会往文件 <head> 里插入一个 <style data-grapesjs-overrides> 块， 用于承载样式面板产生的覆盖样式——这是上游既有行为，属该工具的正常工作方式。
  • 没有提供单文件 exe：启动器以子进程方式调用 scripts/workbench.py， 用 PyInstaller 冻结后 sys.executable 不再指向 Python，需要额外做 argv 分发改造， 不是"打包一下就完事"，所以宁可不做，也不给一个坏掉的 exe。 若目标机器没有 Python，推荐把 Windows 版 embeddable Python 放进 runtime/。
  • 运行要求：Python ≥ 3.9，只用标准库；本机已有 3.13，开箱可用。
